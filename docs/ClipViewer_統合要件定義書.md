# ClipViewer v0.8.3 統合要件定義書

## プロジェクト情報
- **プロジェクト名**: ClipViewer
- **バージョン**: v0.8.3
- **作成日**: 2026/02/22
- **最終更新**: 2026/07/12
- **ステータス**: 実装完了・試用中

---

## 1. 概要

Clip Studio Paint専用フォーマット（.clip）を含む画像ビューワー。
フルスクリーン表示、見開き表示、ズーム機能、ディレクトリ移動、アニメーション再生、アーカイブ内画像表示等を搭載。

---

## 2. 対応フォーマット

### 2.1 画像フォーマット

| 形式 | 拡張子 | 対応方式 |
|------|--------|----------|
| CLIP | .clip | SQLite抽出（CanvasPreview） |
| PSD  | .psd  | Image Dataセクションからフラット画像抽出（RGB/8bit/Raw・PackBits対応） |
| JPEG | .jpg, .jpeg | WPF標準 BitmapImage |
| PNG | .png | WPF標準 BitmapImage |
| GIF（静止） | .gif | WPF標準 BitmapImage |
| GIF（アニメ） | .gif | GifBitmapDecoder フレーム合成再生 |
| WebP（静止） | .webp | Windows Imaging Component |
| WebP（アニメ） | .webp | libwebp P/Invoke（libwebpdemux.dll） |
| AVIF（静止） | .avif | WIC ネイティブ（要 HEIF Image Extensions + AV1 Video Extension） |

### 2.2 アーカイブフォーマット

| 形式 | 拡張子 | 対応方式 |
|------|--------|----------|
| ZIP | .zip | System.IO.Compression（標準ライブラリ） |
| CBZ | .cbz | System.IO.Compression（ZIPと同一） |
| RAR | .rar | 7-Zip CLI（7z.exe 要インストール） |
| LZH | .lzh | 7-Zip CLI（7z.exe 要インストール） |
| 7z | .7z | 7-Zip CLI（7z.exe 要インストール） |

アーカイブ内の画像は `%TEMP%\ClipViewer\` へ一時展開後に通常の画像ファイルとして処理する。
終了時・アーカイブ切替時に一時ディレクトリを自動削除する。

### 2.3 ファイル列挙

```
直接表示:
  対象: *.clip, *.psd, *.jpg, *.jpeg, *.png, *.gif, *.webp, *.avif
  ソート: 自然順ソート（1, 2, 10...の数値認識。混在可）

アーカイブモード:
  起動引数または関連付けでアーカイブファイルを開いた場合、
  内部の画像ファイルを一時展開して同様に列挙・表示する
```

**ソート順（v0.8.1修正）**: 「フォルダ階層 → ファイル名」の2段自然順比較。
複数フォルダ構成のアーカイブ（A/01.jpg, B/01.jpg ...）では、フォルダAの全画像を
表示し終えてからフォルダBに進む（v0.8.0以前はファイル名のみの比較だったため
A/01→B/01 のように交錯する不具合があった）。

## 4. 見開き表示仕様

### 4.1 ページ配置

| モード | 右側 | 左側 |
|--------|------|------|
| 右綴じ（漫画式） | 奇数ページ | 偶数ページ |
| 左綴じ（洋書式） | 偶数ページ | 奇数ページ |

### 4.2 見開き表示判定アルゴリズム（SpreadStepSize）

任意のインデックスを表示する際に「見開き（step=2）」か「単ページ（step=1）」かを決定するアルゴリズム。

#### ツリー図

```
任意画像の表示開始
├── 見開きモードか？
│   ├── 先頭単独表示モードか？
│   │   └── 先頭ページか？
│   │       └── 単ページ表示へ
│   ├── 最終ページか？
│   │   └── 単ページ表示へ
│   ├── 画像フォーマットはアニメGIF or アニメWEBPか？
│   │   └── 単ページ表示へ
│   ├── 次ページの画像フォーマットはアニメGIF or アニメWEBPか？
│   │   └── 単ページ表示へ
│   ├── 縦横比は横長か？
│   │   └── 単ページ表示へ
│   ├── 次ページの画像の縦横比は横長か？
│   │   └── 単ページ表示へ
│   └── 任意画像と次のページ画像を並べて見開き表示＞次の操作まで待機
└── 単ページ表示＞次の操作まで待機
```

#### Yggdra書式

```
<yggdra>
@任意画像の表示開始
   >見開きモード
      >先頭単独表示モードON
         :先頭ページ → 単ページ表示
      :最終ページ → 単ページ表示
      :アニメGIF/WEBP → 単ページ表示
      :次ページがアニメGIF/WEBP → 単ページ表示
      :横長画像 → 単ページ表示
      :次ページが横長画像 → 単ページ表示
      :それ以外 → 見開き表示（次の操作まで待機）
   >単ページモード
      :単ページ表示（次の操作まで待機）
</yggdra>
```

#### アニメ判定の遅延処理

アニメかどうかはファイルを実際に開くまで判断できない。未判定ファイルへの対応は以下の2段階で行う。

1. **初回表示時**: `_knownAnimated` キャッシュ未登録 → 見開き判定を通過し一時的に見開き表示
2. **バックグラウンド判定**: `TriggerAnimationCheckForSpread()` が非同期でフレーム数確認
3. **アニメ確定次第**: `Dispatcher.Invoke` で `DisplayCurrent()` を再呼び出し → 単ページへ自動切替
4. **2回目以降**: `_knownAnimated` ヒットにより即単ページ表示

### 4.3 フィット方式

- 2画像合計で画面幅にフィット
- 各画像は画面幅の約50%を上限
- アスペクト比維持

### 4.4 画像間マージン

- 2画像間（ノド部分）: 余白なし、密接配置

## 5. アニメーション機能仕様

### 5.1 対応フォーマット

| フォーマット | デコード方式 |
|------------|------------|
| アニメGIF | `GifBitmapDecoder` でフレーム合成（disposal メソッド対応） |
| アニメWebP | `libwebpdemux.dll` P/Invoke（`WebPAnimDecoderNewInternal`） |

静止GIF・静止WebP（フレーム数=1）は通常の静止画として表示する。

### 5.2 再生エンジン

`CompositionTarget.Rendering` + `Stopwatch` によるvsync駆動型再生。DispatcherTimerより高精度で、17ms/frameのGIF・WebPを正確な速度で再生できる。

| 項目 | 値 |
|------|-----|
| 精度補正 | 2ms 早め判定でvsyncズレを吸収 |
| ドリフト防止 | 目標時刻を絶対値で積算（相対加算なし） |

### 5.3 再生モード（F5キー切替）

| モード | 動作 |
|--------|------|
| Loop（ループ） | 無限ループ再生 |
| AutoAdvance（自動遷移） | 1ループ完了後、次のファイルへ自動移動 |

AutoAdvanceモードでは、連番アニメWebPファイルをシームレスに連続再生できる。

### 5.4 アニメ制御キー（デフォルト）

| キー | 動作 |
|------|------|
| F5 | Loop↔AutoAdvance 切替 |
| F6 | 一時停止／再生 |
| F7 | コマ送り（前進） |
| F8 | コマ戻し（後退） |

### 5.5 必要DLL（WebPアニメ用）

| DLL | 役割 |
|-----|------|
| `libwebp.dll` | WebPコアライブラリ |
| `libwebpdemux.dll` | アニメデコード（P/Invoke対象） |
| `libsharpyuv.dll` | 色変換補助（libwebp依存） |

vcpkg x64-windows で取得。実行ファイルと同ディレクトリに配置する。

## 6. アーカイブ対応仕様

### 6.1 動作フロー

```
起動引数にアーカイブファイルが指定された場合
  → %TEMP%\ClipViewer\{アーカイブ名}_{ランダム8文字}\ に画像のみ展開
  → 展開済みファイルで _clipFiles を構築
  → 通常の画像表示フローへ
```

### 6.2 フォーマット別展開方式

| 拡張子 | 方式 | 前提 |
|--------|------|------|
| .zip / .cbz | `System.IO.Compression.ZipFile` | 追加依存なし |
| .rar / .lzh / .7z | `7z.exe` 外部プロセス | 7-Zip のインストールが必要 |

### 6.3 アーカイブ間ナビゲーション

アーカイブモード時、↑/↓キーで同フォルダ内の前後アーカイブへ移動する。
移動時は前のアーカイブの一時ディレクトリを削除してから次のアーカイブを展開する。

### 6.4 クリーンアップ

| タイミング | 動作 |
|-----------|------|
| アーカイブ切替時 | 前回の一時ディレクトリを削除 |
| アプリ終了時 | 現在の一時ディレクトリを削除 |

## 7. ズーム機能仕様

### 7.1 ズーム操作

| 操作 | 動作 |
|------|------|
| ホイール上 | 拡大（+20%） |
| ホイール下 | 縮小（-20%） |

**スナップ（v0.8.0）**: ホイール1ステップが「Fit」または「原寸100%」をまたぐ場合、通り過ぎずにその点へ吸着する（次のステップで離脱）。両方をまたぐ場合はスクロール方向で先に出会う方に吸着。ズーム率表示（F43）はオリジナル原寸=100%基準。

### 7.2 ズームパラメータ

| 項目 | 値 |
|------|-----|
| 倍率範囲 | 10% 〜 500% |
| 倍率刻み | 20% |
| ズーム中心 | 画面中央 |
| 初期倍率 | Fit（画面フィット） |

### 7.3 見開き時の挙動

- 2画像を1つの画像として扱う
- ズーム・ドラッグは統合された状態で適用

### 7.4 ドラッグ移動

| 項目 | 値 |
|------|-----|
| 操作 | マウス左ボタンドラッグ |
| 範囲制限 | なし（自由移動） |

### 7.5 状態管理

| 状況 | 動作 |
|------|------|
| ページ送り/戻り | ズーム倍率リセット（Fitに戻る） |
| 終了時 | ズーム状態は保存しない |

## 8. ディレクトリ/アーカイブ移動仕様

### 8.1 通常モード（ディレクトリ移動）

- 同一親ディレクトリ内の兄弟ディレクトリのみ対象
- 対象ファイルが存在しないディレクトリはスキップ

```
例: C:\Images\Folder2\image.clip 表示中

C:\Images\
  ├── Folder1\  ← ↑キーで移動
  ├── Folder2\  ← 現在
  └── Folder3\  ← ↓キーで移動
```

### 8.2 アーカイブモード（アーカイブ間移動）

- 同フォルダ内の兄弟アーカイブファイルを対象
- 自然順ソートで並べて前後移動

### 8.3 共通動作

| キー | 動作 |
|------|------|
| ↑ | 前へ（先頭ファイル表示） |
| ↓ | 次へ（先頭ファイル表示） |

| 状況 | 通知 |
|------|------|
| 最初で↑ | 最上位ディレクトリです / 最初のアーカイブです |
| 最後で↓ | 最下位ディレクトリです / 最後のアーカイブです |

## 9. 外部連携機能

### 9.1 外部エディタ起動（Ctrl+E）

- 表示中ファイルを外部アプリで開く
- 見開きモード時は右側ファイル

### 9.2 ファイル保存（Insert）

- 表示中ファイルを指定ディレクトリにコピー
- 見開きモード時は右側ファイル
- 元ファイルをそのままコピー（変換なし）
- 成功時：「〇〇.xxx を保存しました」を1秒間通知表示

### 9.3 クリップボードコピー（Ctrl+C）

- 表示中画像をクリップボードにコピー
- アニメ再生中の場合はコピー時点のフレーム静止画をコピー
- 見開きモード時は右側画像のみ
- 除外対象: .clip, .psd（多層レイヤーフォーマット）
- 成功時：「クリップボードにコピーしました」を1秒間通知表示

### 9.4 ファイルをダイアログ保存（Ctrl+S）

- 標準Windowsファイルダイアログで保存先を指定してファイルをコピー
- 見開きモード時はファイル名が若い方（`_currentIndex`）を対象
- 元のファイル名がダイアログに入力済みの状態で開く（リネームも可）

## 10. 表示スクリーン指定仕様

### 10.1 概要

マルチモニタ環境において、アプリの表示先モニタを ini ファイルで指定する。
SendTo 等でサブモニタ側から起動した場合でも、指定モニタに強制表示される。

### 10.2 動作仕様

| 項目 | 値 |
|------|----|
| 取得方法 | System.Windows.Forms.Screen.AllScreens 配列の添字 |
| 0 | プライマリモニタ |
| 1以降 | 接続順（AllScreens の配列順） |
| 範囲外指定時 | プライマリモニタにフォールバック |

## 19. フィルタ仕様（F49/F50、v0.7.0新設）

### 19.1 構成（2段パイプライン）

```
元画像
  ↓ ヘッダのみ読んでソース原寸を取得
[判定] ダウンスケールか？（Fit表示スケール < MoireDownscaleThreshold かつ < 1.0）
  ├─ No → パイプライン全体をバイパス（等倍・拡大時は素通し）
  └─ Yes ↓
[デコード時縮小] 目標幅の2倍まで DecodePixelWidth で事前縮小（WIC の高品質縮小）
  ↓
[Stage 1] モアレ軽減: Lanczos-3 ダウンスケール（表示サイズへ）
   強度(0-100)をカーネル幅倍率 1.0〜2.0 にマッピング
  ↓
[Stage 2] シャープ化: アンシャープマスク（閾値付き）
  ↓
表示・キャッシュ（プリフェッチもフィルタ済みで先読み）
```

### 19.2 動作仕様

- **ゲーティング**: Fit 表示時の縮小率がしきい値未満のダウンスケール時のみ適用。等倍・拡大時は絶対に適用しない（ぼかさない）。
- **Stage1/Stage2 は独立トグル**（F9 / F11）。両方OFF・片方のみON・両方ONのすべての組み合わせが可能。
  - Stage2 のみ ON の場合も表示サイズへの標準 Lanczos 縮小（倍率1.0）を行った上でシャープ化する（フル解像度への USM は表示上無意味なため）。
- **トグル状態の永続化**: F9/F11 の ON/OFF は終了時に ini の `[Filters]` へ保存され、次回起動時に復元される。
- **キャッシュ**: フィルタ設定・表示領域サイズ・表示モードの「署名」が変化するとページキャッシュを破棄して再フィルタ。ウィンドウリサイズは300msデバウンス。フィルタ全OFF時は署名を固定し、表示条件変化による無駄な再デコードを行わない。
- **先読みの開始タイミング**: 起動時の先読みは Window_Loaded 後に開始（ウィンドウ表示前はディスク/CPUを現在画像に集中させる）。
- **通知**: トグル時に「モアレ軽減フィルタ: ON/OFF」「シャープ化フィルタ: ON/OFF」を1秒表示。
- **Detailed情報パネル**: フィルタ適用中は「原寸 → 表示サイズ px (フィルタ適用)」を表示。

### 19.3 設定項目（ini [Filters]）

| キー | 型 | デフォルト | 範囲 | 説明 |
|------|----|-----------|------|------|
| MoireFilterEnabled | bool | True | — | Stage1 の ON/OFF（F9） |
| MoireFilterMode | enum | Lanczos | Off/Area/Lanczos/Gaussian | Stage1 アルゴリズム。現状 Lanczos のみ実装（Area/Gaussian は Lanczos で代替、Phase 3 で追加予定） |
| MoireFilterStrength | int | 40 | 0-100 | Lanczos カーネル幅倍率 1.0〜2.0 にマッピング。0=標準縮小、100=最強ローパス |
| MoireDownscaleThreshold | double | 0.95 | 0.0-1.0 | この縮小率未満でのみ適用 |
| SharpenEnabled | bool | True | — | Stage2 の ON/OFF（F11） |
| SharpenRadius | double | 1.0 | 0.1-5.0 | USM ガウシアン半径 px |
| SharpenAmount | int | 100 | 0-200 | USM 強度 % |
| SharpenThreshold | int | 4 | 0-255 | この値未満のコントラスト差はシャープ化しない（リンギング防止） |

- レンジ外の値はクランプして通知なく適用（起動を阻害しない）。
- `[Filters]` セクションがない旧 ini はデフォルト値で補完され、次回保存時に追記される。

### 19.4 制限事項

- アニメーション GIF/WebP の再生フレームにはフィルタは適用されない（静止表示の初回フレームのみ適用）。
- フィルタ適用中に大きくズームインすると、表示サイズ相当までダウンスケール済みのビットマップを拡大するため、原寸よりディテールが劣る（デコードは目標幅の2倍を確保しているため2倍ズームまでは劣化しない）。原寸確認時は F9/F11 でフィルタを OFF にする。
- Ctrl+C のクリップボードコピーは「表示中の（フィルタ済み）画像」をコピーする。

## 20. シークバー仕様（F51、v0.8.0新設）

### 20.1 表示・消滅

|------|-----|
| 配色 | オレンジ系（#FF9500） |

## 21. アーカイブ閲覧位置の自動復元（F52、v0.8.0新設）

### 21.1 動作

- アーカイブ閲覧中に「アプリ終了」または「別アーカイブへの切替」を行うと、そのアーカイブのフルパスと表示中画像（アーカイブ内相対パス）を履歴に記録する
- 同じアーカイブを再び開いたとき、履歴に一致するファイルがあれば**そのページから表示を開始**し、「前回の位置から再開（Home で先頭へ）」と1.5秒通知する
- 前回位置が先頭（1枚目）の場合は通常どおり先頭から開始（通知なし）

### 21.2 履歴ファイル

| 項目 | 値 |
|------|-----|
| ファイル | `ClipViewer_history.txt`（exe と同一ディレクトリ） |
| 形式 | `最終閲覧ticks TAB アーカイブフルパス TAB アーカイブ内相対パス`（1行1件） |
| 保持件数 | 最大 `ArchiveHistoryCount` 件（デフォルト30、ini [Settings] で変更可。最終閲覧が新しい順、LRU） |

- アーカイブのパスで照合するため、アーカイブを移動・リネームすると履歴は引き継がれない
- 通常フォルダは対象外（フォルダは「開いたファイルそのもの」から表示開始するのが正であり、復元と競合するため）
- 履歴の読み書き失敗は無視される（本体動作を阻害しない）

### 21.3 機能の ON/OFF

| 項目 | 値 |
|------|-----|
| ini 設定 | `[Settings] ArchiveHistoryEnabled=True/False` |
| キーバインド | `ToggleArchiveHistory`（デフォルト `None`=未割り当て。ini でキー名を指定して有効化） |

- OFF のとき: 記録・復元とも行わない（既存の履歴ファイルは削除されない）
- キーでトグルすると「アーカイブ履歴: ON/OFF」を1秒通知し、状態は終了時に ini へ保存される
